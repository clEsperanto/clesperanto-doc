Pyclesperanto on HPC
====================

This documentation is an example on how to run ``pyclesperanto`` on a SLURM hpc cluster based on our personal experiences and hardware/software setup. It is not guaranteed to work on your cluster exactly as described here, but it should give you a good starting point. Please adapt the instructions to your cluster's environment and software stack.

For this example, we rely on `pixi <https://pixi.sh>`__ and `Apptainer <https://apptainer.org>`__ for deployment: a pixi environment containing ``pyclesperanto``, ``pyclesperanto_opencl`` and ``pyclesperanto_cuda`` is packaged in an Apptainer image (``pixi.sif``).

The CUDA and OpenCL backends have different requirements on a cluster, so they are documented separately below, please choose the appropriate one for your needs.

.. important::

    Run the CUDA and OpenCL backends in **separate processes** (two separate ``apptainer exec`` calls). See :ref:`hpc-never-mix-backends`.

Common rules
------------

- Always use ``apptainer exec --cleanenv --nv``.

  - ``--nv`` injects the host NVIDIA driver libraries (``libcuda.so``, ``libnvidia-opencl.so``, ...).
  - ``--cleanenv`` prevents the host environment (modules, ``LD_LIBRARY_PATH``, ``CUDA_HOME``, ...) from leaking into the container.

- Forward ``CUDA_VISIBLE_DEVICES`` explicitly with ``--env``, otherwise ``--cleanenv`` drops the GPU assigned by SLURM.
- Avoid loading a host CUDA module (``module load cuda``): pyclesperanto's wheels bundle their own runtime.
- Check the node's driver with ``nvidia-smi`` (driver version, and maximum CUDA version supported).

CUDA backend
------------

Forward compatibility (old driver)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``pyclesperanto`` currently bundles a CUDA runtime and nvrtc (CUDA 12.6). On a cluster with an "old" driver (e.g. 535.183.01, CUDA 12.2), the driver cannot load (JIT) the PTX generated by this newer nvrtc, and kernels fail to build/load.

.. important::

    For more recent CUDA versions, please open an issue on `GitHub <https:://github.com/clEsperanto/pyclesperanto/issues>`__ for support. We will try to provide a wheel with a newer CUDA runtime.

Rule of thumb: if the CUDA version bundled in the wheel is newer than what the driver supports, you need the CUDA forward-compatibility libraries (see `NVIDIA documentation <https://docs.nvidia.com/deploy/cuda-compatibility/forward-compatibility.html>`__).

1. Download the ``cuda-compat-12-6`` ``.deb`` package from NVIDIA's CUDA repository (match the CUDA version bundled in the wheel).
2. Extract it without root, e.g. ``dpkg-deb -x cuda-compat-12-6_*.deb extracted/``.
3. Keep the directory containing the compat ``libcuda.so*`` (typically ``extracted/usr/local/cuda-12.6/compat``) and use it as ``CUDA_COMPAT_DIR``.
4. At run time, bind it read-only and put it on ``LD_LIBRARY_PATH`` **for the CUDA process only**.

Limits: forward compatibility is only supported on data-center GPUs (e.g. A100, H100), and the host kernel driver must be a branch supported by the compat package.

Module conflict
~~~~~~~~~~~~~~~

Host CUDA modules export an ``LD_LIBRARY_PATH`` that contains a stub ``libcuda.so``. It shadows the real driver library injected by ``--nv``, making the driver look old and breaking PTX loading. Use ``--cleanenv`` and avoid loading a CUDA module.

SBATCH example
~~~~~~~~~~~~~~

.. code:: bash

    #!/bin/bash

    #SBATCH --job-name=pyclesperanto
    #SBATCH --output=slurm_%j.out
    #SBATCH --error=slurm_%j.err
    #SBATCH --partition=g
    #SBATCH --gres=gpu:1
    #SBATCH --cpus-per-task=2
    #SBATCH --mem=10G
    #SBATCH --time=01:00:00

    # Path to the Apptainer pixi image
    CONTAINER=$HOME/pixi.sif

    # CUDA forward-compatibility libs (see section above)
    CUDA_COMPAT_DIR="$HOME/cuda-compat-12-6"

    # No CUDA module: the pixi env ships its own runtime/nvrtc
    module unload cuda 2>/dev/null || true
    unset CUDA_HOME CUDA_PATH CUDA_ROOT LD_LIBRARY_PATH

    APPTAINER_BINDS="$PWD:$PWD,$CUDA_COMPAT_DIR:$CUDA_COMPAT_DIR:ro"

    apptainer exec --cleanenv --nv \
        --env "CUDA_VISIBLE_DEVICES=${CUDA_VISIBLE_DEVICES:-}" \
        --env "LD_LIBRARY_PATH=${CUDA_COMPAT_DIR}" \
        --bind "$APPTAINER_BINDS" --pwd $PWD "$CONTAINER" pixi run python my_cuda_script.py

Troubleshooting
~~~~~~~~~~~~~~~

.. list-table::
    :header-rows: 1
    :widths: 50 50

    * - Symptom
      - Likely cause / fix
    * - ``CUDA_ERROR_UNSUPPORTED_PTX_VERSION``, ``CUDA_ERROR_INVALID_PTX``, "driver version is insufficient"
      - Driver older than bundled CUDA: use forward compatibility.
    * - Same errors even with compat libs
      - A host CUDA module or ``LD_LIBRARY_PATH`` is leaking a stub ``libcuda.so``: use ``--cleanenv``, unload the module.
    * - 0 devices visible
      - Check ``--gres``, ``--nv``, and that ``CUDA_VISIBLE_DEVICES`` is forwarded with ``--env``.

OpenCL backend
--------------

ICDs
~~~~

The OpenCL ICD loader needs to know where the vendor ICDs (e.g. ``nvidia.icd``) are. ``--nv`` alone does not provide this, so the host registry must be bound into the container:

.. code:: bash

    --bind /etc/OpenCL/vendors:/etc/OpenCL/vendors

The path can differ between clusters; check that it exists on the compute node.

No compat libs
~~~~~~~~~~~~~~

The ``cuda-compat`` package only replaces ``libcuda.so``, not ``libnvidia-opencl.so``, which stays at the host driver version. The OpenCL process must therefore use the real driver libraries: **do not** bind the compat directory nor set ``LD_LIBRARY_PATH`` for it.

SBATCH example
~~~~~~~~~~~~~~

.. code:: bash

    #!/bin/bash

    #SBATCH --job-name=pyclesperanto
    #SBATCH --output=slurm_%j.out
    #SBATCH --error=slurm_%j.err
    #SBATCH --partition=g
    #SBATCH --gres=gpu:1            # or a specific model, e.g. gpu:A100:1
    #SBATCH --cpus-per-task=2
    #SBATCH --mem=10G
    #SBATCH --time=01:00:00
    ##SBATCH --exclude=node1,node2  # optional: skip nodes with a broken driver

    # Path to the Apptainer pixi image
    CONTAINER=$HOME/pixi.sif

    # Bind the host's OpenCL ICD registry so the NVIDIA OpenCL platform is
    # discoverable inside the container (--nv alone does not do this for OpenCL).
    APPTAINER_BINDS="$PWD:$PWD"
    if [ -d /etc/OpenCL/vendors ]; then
        APPTAINER_BINDS="$APPTAINER_BINDS,/etc/OpenCL/vendors:/etc/OpenCL/vendors"
    fi

    apptainer exec --cleanenv --nv \
        --env "CUDA_VISIBLE_DEVICES=${CUDA_VISIBLE_DEVICES:-}" \
        --bind "$APPTAINER_BINDS" --pwd $PWD "$CONTAINER" pixi run python my_opencl_script.py

Troubleshooting
~~~~~~~~~~~~~~~

.. list-table::
    :header-rows: 1
    :widths: 50 50

    * - Symptom
      - Likely cause / fix
    * - No OpenCL platform / device found (``CL_PLATFORM_NOT_FOUND_KHR``), while ``nvidia-smi`` works
      - ICDs not visible: bind ``/etc/OpenCL/vendors``.
    * - Works on small buffers, hangs or kills the job on large ones (e.g. 2048 MB)
      - CUDA compat ``libcuda.so`` loaded in the same process: see :ref:`hpc-never-mix-backends`.

.. _hpc-never-mix-backends:

Never mix both backends in one process
--------------------------------------

If CUDA (with the compat ``libcuda.so``) and OpenCL are used in the **same process**, the compat ``libcuda.so`` is loaded first and the OpenCL ICD (built against the host's R535 driver) reuses it instead of its matching sibling. This version-skewed pairing "mostly works" on small buffers but hangs or crashes on larger ones.

Fix: launch one ``apptainer exec`` per backend, with the compat directory only for the CUDA one. A job running both is simply two sequential calls:

.. code:: bash

    # CUDA: compat libs bound and on LD_LIBRARY_PATH
    apptainer exec --cleanenv --nv \
        --env "CUDA_VISIBLE_DEVICES=${CUDA_VISIBLE_DEVICES:-}" \
        --env "LD_LIBRARY_PATH=${CUDA_COMPAT_DIR}" \
        --bind "$PWD:$PWD,$CUDA_COMPAT_DIR:$CUDA_COMPAT_DIR:ro" \
        --pwd $PWD "$CONTAINER" pixi run python my_cuda_script.py

    # OpenCL: real driver only, ICDs bound
    apptainer exec --cleanenv --nv \
        --env "CUDA_VISIBLE_DEVICES=${CUDA_VISIBLE_DEVICES:-}" \
        --bind "$PWD:$PWD,/etc/OpenCL/vendors:/etc/OpenCL/vendors" \
        --pwd $PWD "$CONTAINER" pixi run python my_opencl_script.py
